# Spec: 账户体系重构 + 自动分类修复

**Status**: implemented
**Created**: 2026-04-19

## 额外修复：空规则下自动匹配问题

**问题**：清空规则后导入账单，仍会自动匹配到已删除规则对应的分类历史
**原因**：`autoClassifyTransactions` 的分类历史匹配（精确+模糊）不依赖规则存在性
**修复**：仅在有规则时启用历史记录匹配，且匹配时验证 categoryId 有效性

## 背景
当前账户只有"自有账户"和"先用后还(credit)"两类。用户需要扩展为三类：自有钱包、应付欠款(负债)、应收欠款(资产)，并在账户详情页直接操作资金变动。

## 需求

### 账户分类
1. **自有钱包**：实际持有、可自由支配的现金余额（核心资产）
2. **应付欠款**（负债账户）：私人借款 + 平台先用后还，统一合并管理
   - 必须绑定债权人（收款方/平台）
   - 可选总额度和还款日（平台信用有用，私人借款为空）
3. **应收欠款**（资产账户）：用户借钱借给他人形成的待收回款项
   - 必须绑定债务人（欠款人）

### 资金变动逻辑（账户详情页直接操作）
| 操作 | 钱包余额 | 应付/应收 |
|------|---------|----------|
| 借入资金（应付增加） | 增加 | 应付欠款增加 |
| 偿还应付（应付减少） | 减少 | 应付欠款减少 |
| 借出资金（应收增加） | 减少 | 应收欠款增加 |
| 收回应收（应收减少） | 增加 | 应收欠款减少 |

### 首页余额
- 总余额 = 自有钱包余额 + 应收欠款总额 - 应付欠款总额

## 实现变更

### 数据模型
- 新增账户分类：`payable`（应付欠款）、`receivable`（应收欠款）
- 废弃现有 `credit` 分类，迁移为 `payable`
- 账户新增字段：`creditorName`（债权人）、`debtorName`（债务人）

### UI 变更
- 账户弹窗：新增"应付欠款"和"应收欠款"选项，移除"先用后还"
- 账户列表：分三栏显示（自有钱包、应付欠款、应收欠款）
- 应付/应收卡片增加操作按钮（借入/偿还/借出/收回）
- 新增 4 个操作弹窗（借入、偿还应付、借出、收回应收）

### 逻辑变更
- `getTotalBalance()` = 钱包 + 应收 - 应付
- `recalculateAllAccountBalances()` 按新分类处理
- `showBalanceDetail()` 显示三类账户

## 验收标准
