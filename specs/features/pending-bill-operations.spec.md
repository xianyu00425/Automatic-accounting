# Spec: 待处理账单操作类型扩展

**Status**: implemented
**Created**: 2026-04-20

## 背景

当前待处理账单只能通过"处理"按钮归类为收入/支出/转账。用户需要支持将待处理账单直接标记为借入、借出、还款、收款操作，并绑定债权人/债务人账户，自动影响对应账户余额。

## 需求

### 操作类型扩展
在处理待处理账单的弹窗中，`process-type` 下拉框新增 4 个选项：
1. **借入** (`borrow_in`)：应付欠款增加，自有钱包增加
2. **借出** (`lend_out`)：自有钱包减少，应收欠款增加
3. **还款** (`repay`)：自有钱包减少，应付欠款减少
4. **收款** (`collect`)：自有钱包增加，应收欠款减少

### 账户绑定逻辑
- **借入**：选择"借入至哪个钱包"（personal账户）+ 自动关联应付账户（根据交易对方匹配 payable 账户的 creditorName）
- **借出**：选择"从哪个钱包借出"（personal账户）+ 选择/创建应收账户（receivable，绑定 debtorName）
- **还款**：选择"从哪个钱包还款"（personal账户）+ 选择应付账户（payable，根据交易对方匹配）
- **收款**：选择"收至哪个钱包"（personal账户）+ 选择应收账户（receivable，根据交易对方匹配）

### 余额影响
- 借入：钱包余额 += 金额，应付欠款 += 金额
- 借出：钱包余额 -= 金额，应收欠款 += 金额
- 还款：钱包余额 -= 金额，应付欠款 -= 金额
- 收款：钱包余额 += 金额，应收欠款 -= 金额

### 交易记录
每种操作生成 2 条交易记录（一条关联应付/应收账户，一条关联钱包账户），与现有的 `executeBorrow`/`executeLend`/`executeRepayPayable`/`executeCollect` 逻辑一致。

## 实现变更

### HTML 变更
- `process-type` select 新增 4 个 option
- 新增 4 个账户选择器字段（借入至钱包、从钱包借出、还款钱包、收款钱包）
- 新增应付/应收账户选择器（根据交易对方自动匹配）

### JS 变更
- `toggleProcessTypeFields()` 新增 4 种类型的字段显示/隐藏逻辑
- `saveTransaction()` 新增 4 种类型的保存逻辑，调用现有的资金变动函数逻辑
- 新增自动匹配应付/应收账户的逻辑（根据交易对方名称匹配 creditorName/debtorName）

- [x] 选择后显示对应的钱包和应付/应收账户选择器
- [x] 确认后账户余额正确更新
